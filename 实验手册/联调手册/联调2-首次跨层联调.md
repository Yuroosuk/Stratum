## 实验二：约定 UART 地址，实现 riscv32 平台 putch

### 目标
两人约定 UART（串口）的 MMIO 地址，成员 B 实现 `platform/riscv32/ioe.c`，成员 A 在 `memory.cpp` 中添加 UART 处理逻辑。

### 背景知识

**MMIO（Memory Mapped I/O）：**  
在没有独立 I/O 指令的架构上（RISC-V 没有 x86 的 `in`/`out` 指令），硬件设备通过"内存映射"的方式暴露寄存器：某个特定的物理地址对应硬件设备的控制/数据寄存器，读写这个地址就是在操作硬件。

UART 只需要最简单的"写"功能：向 `UART_TX` 地址写入一个字节，SCore 检测到这个写操作后，把该字节打印到宿主机终端。

**约定：**  
我们规定 UART 基地址为 `0xa0000000`，发送数据寄存器（TX）偏移为 `0x00`，即：

```
UART_TX_ADDR = 0xa0000000
```

### 步骤

**1. 成员 B：创建 `shal/platform/riscv32/ioe.c`**

```c
#include <am.h>

#define UART_TX  (*(volatile char *)0xa0000000)

void putch(char c) {
    UART_TX = c;   // 向 UART TX 地址写一个字节
}
```

这里用 `volatile` 是告诉编译器"这个写操作有副作用"（真实写了硬件），不能被优化掉。

**2. 成员 A：在 `memory.cpp` 中截获 UART 写操作**

在 `paddr_write` 的开头，在范围检查之前，加入 MMIO 检测：

```cpp
void paddr_write(uint32_t addr, int len, uint32_t data) {
    // UART TX: 写任意字节到 0xa0000000 就打印到终端
    if (addr == 0xa0000000) {
        putchar((char)data);
        fflush(stdout);
        return;
    }
    check_addr(addr, len);
    // ... 正常内存写入 ...
}
```

> ⚠️ 注意：MMIO 区域不在 `MEM_BASE ~ MEM_BASE+MEM_SIZE` 范围内，必须在 `check_addr` 之前处理，否则会触发非法地址 abort。

**3. 协商细节（两人对话）**

在这一步，两人需要确认：
- UART 地址：`0xa0000000`（两边保持一致）
- 写操作的 `len` 参数：UART TX 是一次写一个字节，所以 `len = 1`，`data` 的低 8 位是字符。`putchar((char)data)` 直接取低 8 位，这样处理是正确的。

## 实验三：为 riscv32 平台编译 hello，在 SCore 上运行

### 目标
把 `hello` 用 RISC-V 工具链编译成 ELF，加载进 SCore 运行。

### 步骤

**1. 在 `shal/apps/hello/Makefile` 中增加 riscv32 编译目标**

```makefile
# 添加到 Makefile 中（与 native 目标并列）

RISCV_CC     := riscv32-unknown-elf-gcc
RISCV_CFLAGS := -std=c99 -nostdlib -Wall -I../../include \
                -Ttext 0x80000000 -e main
RISCV_SRCS   := main.c \
                ../../klib/string.c \
                ../../klib/stdio.c  \
                ../../klib/stdlib.c \
                ../../platform/riscv32/ioe.c

hello.elf: $(RISCV_SRCS)
	$(RISCV_CC) $(RISCV_CFLAGS) -o $@ $^
```

> **`-e main`** 指定入口符号为 `main`（通常 ELF 入口是 `_start`，但我们没有 C 运行时初始化，直接从 `main` 开始）。  
> **`-nostdlib`** 告诉链接器不链接 C 标准库。

**2. 编译**

```bash
cd shal/apps/hello
make hello.elf
riscv32-unknown-elf-objdump -d hello.elf | head -40   # 查看前几条指令
```

确认反汇编中 `main` 函数的第一条指令在 `0x80000000`。

**3. 在 SCore 中加载并运行**

```bash
./score/score shal/apps/hello/hello.elf -b
```

**期望输出：**

```
Stratum-Core (SCore) - RISC-V 32-bit Simulator
ELF 已加载，入口地址：0x80000000
Hello, Stratum!
This program runs on the Abstract Machine.
1 + 1 = 2
```

如果看到了这个输出，恭喜你——CPU 模拟器和软件栈第一次成功"对话"了！

**4. 如果没有看到预期输出，逐步排查**

| 症状 | 可能原因 | 排查方法 |
|------|---------|---------|
| SCore 直接 abort（非法地址） | UART 写操作没有在 `check_addr` 之前被截获 | 检查 A 的 `paddr_write` 逻辑 |
| 没有任何输出，程序不退出 | `hello.elf` 没有 ECALL/exit，程序死循环 | 在 `hello/main.c` 末尾加汇编 `ecall`，或者 Ctrl+C 后用 `si` 单步排查 PC 在哪里 |
| 输出乱码 | `putch` 写了 4 字节而不是 1 字节 | 检查 `data` 的处理，确保只取低 8 位 |
| 输出正确但程序无法结束 | 需要 `main` 返回后执行 exit ECALL | 见下面第 5 步 |

**5. 添加程序退出机制**

`main` 函数返回后，程序不知道该做什么（没有 C 运行时来接管）。为裸机程序添加一个出口：

在 `shal/platform/riscv32/` 下创建 `start.S`：

```asm
# shal/platform/riscv32/start.S
.section .text
.global _start
_start:
    call main           # 调用 main()
    # main 返回后，a0 中是返回值（exit code）
    li   a7, 93         # syscall number: exit
    ecall               # 触发 ECALL，通知 SCore 程序结束
```

更新 Makefile：`-e _start`（去掉 `-e main`），并把 `start.S` 加入 RISCV_SRCS。
